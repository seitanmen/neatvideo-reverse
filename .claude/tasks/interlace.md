# インターレース / プログレッシブ対応 (INT-1〜INT-4)

作成: 2026-10-31 (統括)。背景と本家の観測は `docs/INTERLACE_PROGRESSIVE.md` を参照。
実装は **Qt C++ UI (qtui/) と libnvcore (native/)** が対象 (C++ ファースト方針)。
PySide6 版は参照実装として凍結 (変更しない)。

## 共通規約

- プログレッシブ経路は**現状から 1 ビットも変えない** (既定 = progressive)。
  インターレースを指定したときだけ新しい経路を通す。
- 合格判定: ビット一致 + (可能なら) 本家の出力との比較。
- 処理コア Python は触らない。コミットしない。
- REPORT: `work/omo/wp_interlace/REPORT.md` (段階ごとに節を分ける)。

## INT-1: 属性検出 + フィールド分離/再結合ユーティリティ

1. 動画オープン時に ffprobe で `field_order` (progressive / tt / bb / mb / unknown) を
   取得し、UI のフレーム情報に表示する (MeatVideoQt と PySide6 版の両方。表示のみ)。
2. `libnvcore` にフィールド分離/再結合を追加
   (`nv_fields.{h,cpp}`):
   - split(frame) → (top_field, bottom_field) — 高さ = ceil(H/2) の 2 枚。
     インターレースの行オフセット構造 (3-line offset) に対応する
     データ配置 (stride + offset) で持つ (コピーではなく参照で分離できる形)。
   - join(top, bottom) → フレーム。
3. 検証: 分離 → 再結合で元のフレームとバイト一致。
   3-line offset を含む実データ (インターレース素材。ユーザーに依頼するか、
   ffmpeg で 720p48 → 1080i30 変換して作る — `tinterlace` フィルタ) でも確認。

## INT-2: フィールド単位の処理パイプライン

1. 時間フィルタをフィールド系列に対応:
   フィールドの時間順は [n top, n bottom, n+1 top, n+1 bottom, …]
   (本家の Temporal Radius はフィールド数として解釈 — docs §1)。
2. 動き推定をフィールド基準に:
   探索中心の縦座標をフィールド座標 (y/2)、縦方向のブロック境界を
   フィールド境界に合わせる。
3. 空間フィルタはフィールド画像 (高さ半分) にそのまま適用
   (既存の spatial_v5 をそのまま呼べる — 高さが半分になるだけ)。
4. 検証: プログレッシブの合成素材 (動く円 + ノイズ) を
   `tinterlace` でインターレース化したものを
   (a) 現状 (フレーム単位) と (b) フィールド単位で処理し、
   静止部の残差が (b) で大幅に減ることを確認 (数値は REPORT に記録)。
   本家が手元にあれば本家出力との PSNR も比較する。

## INT-3: プロファイル + UI + 書き出し

1. プロファイルのフィールド対応:
   - "Two fields" (両フィールドから作成) / "One field" (Top または Bottom のみ)。
   - プロファイル JSON に `fields` 属性を追加
     (`"fields": "frame" | "two" | "one"`。旧 JSON は frame として読む)。
2. UI: Prepare ページにプロファイル種別の表示、Adjust ページに
   フィールド処理の状態表示。
3. 書き出し: インターレースフラグ (tt/bb) を保持したまま出力する
   (ffmpeg に `setfield` / フラグを渡す。フィールドの順序を壊さない)。
4. 検証: Two fields プロファイル → 処理 → 出力のフラグ確認と、
   プログレッシブ素材での出力が変更前とバイト一致すること。

## INT-4: OFX + 本家比較

1. OFX プロパティでインターレース属性を読む
   (ホストが渡す画像の field 属性。N4 の実装に追加)。
   フィールド処理が必要な場合はホストにフィールド単位のレンダーを要求するか、
   プラグイン内で分離して処理する (OFX の仕様上、プラグイン側で分離するのが単純)。
2. 本家との比較: ユーザーが Resolve で本家 (Two fields プロファイル) を使い
   同じインターレース素材を処理した正解データを取得 → PSNR 比較。
   (本家のフィールド処理の詳細が解読されていないため、数値の完全一致ではなく
   目視 + PSNR の水準比較になる。REPORT にその限界を明記する。)
