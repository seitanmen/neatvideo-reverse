# インターレース / プログレッシブ対応状況 (2026-10-31)

本家 (Neat Video 6.1.3) の実装を基準に、Meat Video の現在の対応状況と残り項目をまとめる。

## 1. 本家の実装 (観測事実)

- **プロファイルの種別**: "Profiled with" の選択肢は本家バイナリの文字列として
  `Full frame` / `Two fields` / `One field` が確認されている (PR #6 の調査で判明。
  「見本の領域サイズ」ではなくフレーム/フィールドの種別を表す欄)。
- **フィールド処理の存在**: RTTI で `astfqg::FilterVideoField` (0x9a17b8) が確認されており
  (Agents.md §6.1「その他」)、フィールド単位のフィルタ関数が存在する。
- **動き補償**: `MotionCompensator::{EstimateScaleMotion, CompensateImageMotion,
  CompensateImageSet}` がフィールド/フレーム両方のレンダーモードで使われる
  (CompensateImageSet = 複数画像 = フィールドの集合を示唆)。
- **処理の推定構造** (解析から):
  - インターレース入力は上下フィールドに分離され、各フィールドが独立した
    画像 (高さ = フレームの半分) として時間フィルタ・空間フィルタ・動き推定に渡る。
  - 動き探索の縦座標はフィールド基準 (フレーム基準の 1/2)。
  - 時間半径は「フィールド数」単位 (radius 2 = 2 フィールド = 1 フレーム分ではない。
    本家 UI の Temporal Radius はフィールド処理時にフィールド数を数える)。
  - 処理後に 3 線 (3-line) オフセットで再結合する。
- 本家 OFX 版はホスト (Resolve) からフィールド情報 (インターレース属性) を
  OFX プロパティで受け取り、フィールド/プログレッシブを切り替える。

## 2. Meat Video の現在の対応状況

| 項目 | 状態 |
|---|---|
| プログレッシブ処理 (全編) | **対応済み** (v5 の既定経路。C++ qtui / libnvcore で動作) |
| インターレース入力の検出 | **未対応** (コンテナ/コーデックの field order 属性を読んでいない) |
| フィールド分離 (Top/Bottom) | **未対応** (フレーム単位で処理している) |
| フィールド単位のプロファイル (Two fields / One field) | **未対応** (Full frame 相当のみ) |
| フィールド単位の時間フィルタ | **未対応** (radius はフレーム数として動作) |
| フィールド単位の動き推定 | **未対応** (フレーム基準の座標系) |
| フィールド再結合 (3-line オフセット) | **未対応** |
| OFX プロパティ経由のフィールド属性 | **未対応** (N4 で実装予定) |
| プログレッシブ素材の出力互換 | **対応済み** (変更前 C++ ビルドとバイト一致) |

補足: インターレース素材を現状の Meat Video に通すと、
「フィールドの交互の表示行を 1 フレームとして扱う」ため、
動き推定と時間平均が正しく働かず、残像や縦方向のノイズ残りが発生する
(本家にインターレース処理を任せた場合と比べて劣る)。

## 3. 残りの対応事項 (実装順)

1. **入力のフィールド属性の検出**: コンテナ (ffprobe の
   `field_order = tt/bb/mb/unknown`) とコーデック内部フラグを読み、
   progressive / interlaced (tt, bb) を判定する。
2. **フィールド分離/再結合ユーティリティ**: フレームを 2 フィールドに分離
   (各行間引き) し、処理後に正しい行オフセットで再結合する。
   インターレースの行構造 (3-line offset) を崩さない。
3. **フィールド単位の時間フィルタ**: フィールドを時間系列として扱う
   (フレーム n の Top フィールド → n の Bottom フィールド → n+1 の Top …)。
   Temporal Radius は本家同様フィールド数として解釈する。
4. **フィールド単位の動き推定**: 探索中心の縦座標をフィールド基準に
   (/2 して丸める)、類似度の縦方向ブロック境界をフィールド基準にする。
5. **プロファイルのフィールド対応**: "Two fields" (両フィールドから
   プロファイルを作る) / "One field" (1 フィールドのみ) の 2 モード。
   プロファイルの JSON に `fields` 属性を追加する。
6. **UI**: Prepare ページにフィールド種別の表示と選択、
   処理中のフィールド数カウンタの表示。
7. **OFX (N4)**: ホストから渡される画像のインターレース属性プロパティを読み、
   フィールド処理が必要な場合はフィールド単位でレンダーを要求する
   (OFX の interlace プロパティ群)。
8. **検証**: 本家でインターレース素材を処理した正解データを取得し、
   PSNR/ビット比較で検証する (インターレース素材のサンプルが必要)。

## 4. 優先順位と依存

- 1〜2 は小規模 (独立したユーティリティ)。3〜5 が本体 (時間フィルタ・
  動き・プロファイルのフィールド化)。
- N4 (OFX) は「まずプログレッシブのみ」で開始し、7 のフィールド属性は
  プロパティを読んで「インターレース非対応」と正直に報告する段階から
  始めるのが安全 (ホスト側のフィールド処理に任せる選択肢もある)。
- 8 は正解データの取得が前提 (ユーザーが Resolve で本家の
  Two fields プロファイルを作成・処理する必要がある)。
