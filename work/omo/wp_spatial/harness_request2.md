# ハーネス要求 2 (2026-10-21、spatial-align): `nvh sel2 … full` (FUN_0098eba8 そのもの)

差分 `nvh_patch2.diff` (`patch -p1 --dry-run` 可、パッチ後の nvh.c は `clang -fsyntax-only -Wall` で警告なし。ビルドしていない)。
既存の `sel2` に第 13 引数 `full` を足し、FUN_009f19cc の代わりに FUN_0098eba8 を同じ引数で呼ぶ。全 n 個を書き出す。

## 目的
移植の `leaf_sel2` は n & 3 の端数部 (0x98ec4c〜0x98ed10 のスカラーの式) を使う (方向経路の面の大きさ w·h は 4 の倍数とは限らない)。
FUN_009f19cc は先頭 n & ~3 個しか処理しないので、端数部は今まで照合できていない (検証者の指摘)。

## 葉ではない点と、それでも安全とみる根拠
- FUN_0098eba8 (0x98eba8、396 B) は外の関数を 1 つだけ呼ぶ: 0x98ec2c `bl 0x9f19cc` (承認済みの葉、`sel2` で照合済み)。それ以外の
  b/bl/blr/br はなく、ret は 1 つ (0x98ed30)。大域は 0x98ebf0〜0x98ebf8 の NEON 判定のバイト 0x14a67a8 (ldrb) だけ。
- 書き込みは引数のポインタ (out x4・best x5・b x1・i4 x3) だけ。スタック枠 0x80 B は callee-saved の退避と 9f19cc への引数。
- 引数の詰め方: 0x98ebe8〜0x98ebec で [x29+0x10] (flag、1 B)・[x29+0x18] (stride)・[x29+0x20] (n) を読み、9f19cc に同じ形で渡す。
  承認済みの `sel2` で 9f19cc に渡している形と同じ (flag 1 の 16 件で b・i4 の書き戻しまで一致済み)。
- 判断は統括に委ねる (「外の関数を呼ばない」条件は満たさない。呼ぶのは照合済みの葉だけ)。

## 照合の準備
`verify/verify_align_leaves.py` は nvh の使い方の表示に `[full]` があるときだけ、n = 1〜1001 (n % 4 ≠ 0 を含む) の `sel2full` を足す。

要求しない。移植 (`ixform` の端数部) は静的な読みのまま (未照合)。
