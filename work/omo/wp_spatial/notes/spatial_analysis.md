# 空間フィルタ (Filter 0x9ac2b0) の静的解析ノート

作成 2026-10-17 (wp_spatial 作業者)。ソース: `notes/dec/` の逆コンパイル (前任作業者が Ghidra 12.1.4 で
出力。ルート 0x9adc8c / 0x9ac2b0 / 0x9a17b8 深さ 4、0x990f74 深さ 2) と `notes/disasm_fn_*.txt`
(自前で `otool -tv` を出した全文逆アセンブリ `tmp/disasm_full.txt` 3,287,476 行から切り出し)。
観測 (実行・逆アセンブルで確かめたこと) と推定を区別する。アドレスは arm64 スライス。

## 1. 呼び出し構造 (観測)

```
FilterVideoField 0x9a17b8   1 フィールド分の全体流 (motion comp → temporal → spatial 等)
  └ Filter 0x9ac2b0         空間フィルタの入口 (パスのループ、プロファイル未初期化なら警告)
      ├ FUN_009c7318        領域/全面の切り出し (Auto Profile と共用)
      ├ FUN_00addccc        チャンク (タスク) 分割の準備
      ├ FUN_00a06540        1 パス分のパラメータ構築 (設定値 → cfg 構造体)
      ├ FUN_00ac2088        平面バッファの確保・色変換 (host RGBA→内部 RGB float)
      ├ FUN_009fc6e8        スレッドプール dispatch (ワーカー = DAT_013fcf40 表の lambda)
      │   └ slot0 lambda 0x9bfea8 → FUN_009ad8c8 (CPU/GPU 振分)
      │       ├ GPU: FUN_009e9940 (CoreGraphics/Metal 系。未解析)
      │       └ CPU: FUN_009adc8c  ← 今回の主対象
      ├ FUN_00ac2c0c         結果の平面を書き戻し
      └ FUN_009a4c10         チャンク分割の後始末
```

- `Filter 0x9ac2b0` 内の `do {...} while (bVar8)` はエラーフラグ (obj+0x25bca) が立ったときの
  再試行ループで、正常時は 1 パス (観測: 制御フローの読み)。
- 幅か高さが 0x30 (48) 未満のときもFUN_009c7318 だけ呼んで uVar11=1 を返す (本家が 48px 未満を
  特別扱いする他の箇所と整合。観測)。
- 各所に難読化された改ざん検知コード (DAT_01487xxx / DAT_01488xxx へのハッシュ書き込み、
  `17 − popcount(…)` 型の係数、トークン表参照) が混在。**回避・パッチはしていない** (COMMON §3)。
  正常系 (ハーネス条件) での影響は以下の注記のとおり観測のみ記録:
  - `0x9ae918` 内: `DAT_01561dec & 0x3fffff == 1` のとき popcount 系の値 iVar7 が立つと
    `DAT_01561d58 = 1` を書く。この語は EstimateNoiseLevelCurve 移植 (Agents.md §6.5) で
    「線カーネルのシフト量。移植は 0 と仮定」としているものと同一 (観測)。
  - `0x98edb0` 内: popcount 系が 0xf でないとき最粗段の cfg ゲイン (`cfg + (levels-1)*4`) を 0 にする
    (観測)。ハーネスで観測された範囲ではこの書き込みが実効した形跡は無い (既存の nvh 照合と
    矛盾しない)。正規ホストでの値は未確認。

## 2. CPU 空間フィルタ本体内核 (観測)

### 2.1 FUN_009adc8c (チャンク並列の外周)
タスクキューから (x0, y0, w, h, …) を取り、`FUN_009c06cc` で入力平面 (obj+0xb0/0xb8/0xc0 の 3 面、
+0xf0 は色モード) からチャンク領域を抽出し、`FUN_009ae918` で処理、`FUN_009af2f8` で
出力平面 (param_4 の 3 面) へ書き戻す。param_6/7/8 は 3 平面ずつの追加出力 (帯域別デバッグ出力と
みられる。推定)。`FUN_009c06cc` は行単位のコピーで、FUN_009f0618/009f0724 は 8/16bit 成分離した
高速コピー (観測: 引数と分岐)。

### 2.2 FUN_009ae918 (1 チャンク、RGB → 3 出力平面)
1. `FUN_009aae90(ctx, R, G, B, w, h, …, σbuf1, σbuf2, σbuf3, 0, levels+1, …)`
   **ノイズ σ マップの構築** (下記 2.3)。
2. vtable `DAT_0147df50[mode](R, G, B, → P1, P2, P3, n)`: 色変換 (RGB → モード別の 3 平面。
   DAT_0147dfb0 (§6.4 の合成表) の逆方向にあたる。推定: モード 1 = Y/Cr/Cb)。
3. 各平面 cについて `FUN_0098edb0(ctx, P_c, OUT_c, σbuf_c, w, h, …, cfg_c = ctx+0x7a2/0x7bc/0x7d6,
   model_c = ctx+0x2e66/0x19284/0x363b, var_out_c, …)` — **マルチスケール縮小ノイズ除去** (2.4)。
   `param_19 & 1` のとき (輝度のみ処理?) 平面 2/3 は memcpy で素通し (観測)。
4. クロマ ブレンド: profile+0x110 (共通) × +0x114/+0x118/+0x11c (面別) を f として
   `OUT = (1−f)·入力 + f·処理結果` (FUN_009ee1a4 = a·x + b·y)。f = 1.0 ならスキップ。
   **f は「残留ノイズ (Noise Level) 系」の混合比と解釈** (推定)。
   f ≠ 1 のとき `FUN_009987ac(ctx, P_c, σbuf_c, …)` が σ マップを処理結果の平面から再測定し、
   var_out (5 段 × n) を同じ f でブレンドして次段 (時間フィルタ) へ渡す (観測: 制御フロー)。
   var_out は時間フィルタの残留ノイズ分散の受け皿 (§6.1 の時間側と対になる。推定)。

### 2.3 FUN_009aae90 (σ マップ構築) — 観測
- vtable `DAT_0147df80[mode]` が 3×3 行列 m[3][3] (9 float) を返す (色モード別)。
- 段 k = 0..levels で、RGB 各面を `FUN_00990d2c` (2×2 平均での 1/2 縮小、blur なし) で段々に縮小。
- ctx+0x11548 / +0x1349c / +0x153f0 (+ (k+ch)·4) の 3 つのモデル値 a_j を二乗し、
  `scale_c = 1 / Σ_j m[c][j]·a_j²` (改ざん検知の popcount 係数は正常時 1)。
- 段のバッファ (FUN_00990d2c の出力) は **輝度ビン化されたインデックス平面** (byte)。
  σ_c² (画素) = scale_c · Σ_j m[c][j]² · a_j² · T_j[bin_j(x)]、ここで T_j は ctx+level·0x404 基準の
  3 つのテーブル (+0x00, +0x14, +0xb8。バイト インデックス)。小平面 (>=5px) は FUN_009f1d8c の
  融合版、それ以外は FUN_009ed3e0 (√|x|·k) で σ = √(·) (観測)。
- σ を `FUN_00993df0` ((3,1)/4 ·2 倍拡大) で 1 段精細側へアップサンプルして σbuf_c+off[k] に格納。
- **プロファイルの輝度別テーブル (BuildNoiseModel の +0xbf40 の 9 ビン曲線に対応すると推定) を
  段ごと・出力平面ごとに画素単位で引用する仕組み**。テーブルの実数値はハーネス未取得。

### 2.4 FUN_0098edb0 (1 平面のマルチスケール処理) — 観測 + 一部推定
- cfg (param_8) レイアウト (オフセットは観測、意味の一部は推定):
  +0x00 σ_cfg[5] (段ごとの水準)、+0x14 amount[5] (段ごとの効き)、+0x28 ?[5]、+0x3c ?[5]、
  +0x50 gain[5] (adaptive/pattern 系のゲイン)、+0x78 ?、+0x90 ?、+0xa4 int、+0xb8 adaptive 係数、
  +0xc0 段数 levels (2..5+)、+0xc8 方向フィルタ組番号 (DAT_01243988 系)。
  model (param_9) は +0x14+4k に段ごとの値、+0x7e4/+0xe24 (組 x 段) に -1e6 以外なら
  大口径構造判定用のしきい値 (観測)。
- 分解: L_0 = 平面。各段 k: `blur = box3×3(L_k)` (FUN_009ed014、×1/9、端は複製/折返しフラグ)、
  `L_{k+1} = ½↓(blur)` (FUN_009f15b4 = 隣接 2×2 平均、床除算)、
  `B_k = L_k − ↑(L_{k+1})` (FUN_00990da8 = 993df0 拡大して差)。↑ は (3,1)/4 分離双一次 ×2
  (FUN_00993df0: 出力 2w (+奇数フラグで +1)、端複製、flip フラグあり)。
  **間引きラプラシアン金字塔 (a-trous ではなく縮小金字塔)** — v5 との最大の構造差。
- 再構成 (粗→細、段 k = levels−1..0):
  1. `W = B_k / (σ_k + 0x38d1b717)` (ε = 9.4433e-4。FUN_009ed5f8 = 1/(x+ε)、FUN_009edc38 = a·b)。
     白色化。バッファは in-place (タイル分岐のアドレス関係から観測)。
  2. `FUN_00990f74` (下記 2.5) で縮小: `S = −amount_k · X`。
  3. `ACC = ↑(ACC) + S·σ_k` (FUN_009edeb8 = z + a·x·y、a=1.0)。ACC は事前に 0 埋め
     (FUN_009f13bc の 4 バイトパターン埋め。観測)。
- 最終: `OUT = 入力平面 + ACC` (FUN_009ed844 = a+b)。S·σ ≈ −A·B·w (σ が約分) なので
  **OUT = 入力 − A·(ノイズらしい帯域成分)** と等価 (σ の約分は推定、符号と加算は観測)。
- var_out (param_10): 段ごとの寄与を ↑ して確定スケールで FUN_009ee304 (×s) /
  FUN_009ed978 (min(s·x, y)?) で書く (観測: 制御フロー)。s = pow(1.25, level) (フラグ時)。
- タイリング: FUN_0099c694 が段ごとの矩形 (x, y, w, h) を計算し、大きい段では矩形ごとに
  同じ処理 (prefetch 付き)。閾値・矩形生成の詳細は未精読 (推定: CPU キャッシュ対策)。

### 2.5 FUN_00990f74 (縮小核) — 観測 (定数は実測)
入力: 白色化帯域 W、invσ (出力バッファ兼用)、w, h, 段 k, cfg, model, …
- `R = √(box3×3(W²))` (FUN_009950f4。§6.1 と同じ局所 RMS)。
- `t = (σ_cfg[k] + 1e-6)·|model[k]|·1.1`。
- **高速経路** (方向フィルタ組が無効/しきい値 -1e6/画面が小さい):
  `X = W · clamp((2t − R)/t, 0, 1)` (FUN_009eebf8 = ランプ重み乗算、両端 ±1e-5 の拡大付)。
  R ≤ t (平坦 = ノイズ) → 1、R ≥ 2t (構造) → 0。
- **方向フィルタ経路** (DAT_01243978[set] が真、BuildNoiseModel と同じ 4/8/16 方向の線フィルタ表):
  - FUN_00990448 (線カーネル生成、画素ノイズ推定 FUN_00998d98 と同一) で各方向のカーネルを構築。
  - 各方向: FUN_009944c0 (線フィルタ)、FUN_009ef260(t, …) または (平滑化後に) FUN_009ef0d0(0.75t, …)
    で方向エネルギー、FUN_009ee5fc/0098ed34/0098eba8 で argmax 方向の選択と 2 択マージ。
  - 大口径構造判定 (model+0x7e4 / +0xe24 ≠ -1e6、lVar23/lVar22 = DAT_01243b68/01243b88 の半径):
    bVar9/bVar8 が立ち、しきい値が 1.75t·(1+0.25·cfg[k+0x78]) 等に拡大 (fVar44/fVar45 の式は観測)。
  - `FUN_009ee93c` (clamp 線形ランプ、§6.1 と同じ) で重み化、最後に FUN_009eebf8/009ee7bc で X を確定。
  - cfg[k+0x50] (gain) > 0 かつ DAT_01243978[set] のとき FUN_009ad06ec/009ad42b8/00ad2964 —
    **BuildNoiseModel の組 4 と同じ自己相似パターン解析 (FUN_00ad319c 系) をフィルタに転用**
    (周期的な固定パターン (細かいテクスチャ) の保護とみられる。推定)。
- 最終: `dst = scale·X` (FUN_009ee304)。scale = −amount (通常)。
  cfg[0xb8] > 0 の adaptive 変種は FUN_009ee7bc (オフセット付きランプ乗算)。
- var 出力 (param_11): X の二乗を 4 回平滑化 (√ 2 回) して 0.01 を加えた除算 (FUN_009ee04c =
  a/(b+ε) 系) — 段ごとの残留分散マップ (推定)。

## 5. 2026-10-17 追記 (呼び出しサイトの引数確定・§2.5 の訂正・区間 A/B 実測)

- FUN_00990f74 の実引数 (FUN_0098edb0 内の bl、`notes/dec/fn_0x98edb0.c:483` / 逆アセンブリ 888 行目。
  観測): `(core, 白色化帯域, dst, dst 同一, w, h, level, cfg, model, acc, sc1, sc2, 行選択, パターン文脈)`。
  呼び出し後に呼び出し元が `FUN_009edeb8(1.0, dst, σbuf, ACC, ACC, n)` で `ACC += dst·σ` を行う
  (§2.4 の再構成 3 のとおり)。
- **§2.5 の訂正 (通常経路の出力スカラー)**: `dst = (1−uVar27)·(−model[+0x14+4·level])·X`
  (fn_0x990f74.c:850。fVar47 = model[+0x14+4·level] は 207 行目。観測)。
  通常経路の scale は **model 側の値**で、cfg+0x14+4·level の amount は適応経路
  (cfg[+0xb8] > 0、ee7bc ブレンド、853 行目) で使う。§2.5 の「scale = −amount (通常)」は誤り。
  したがって通常経路では Noise Reduction Amount は本体に入らず、上流 (FUN_00a06540 の cfg 構築、
  おそらく σ_cfg[k] への乗算) で効くとみられる (推定)。
- 移植 `src/nv_spatial.py` の縮小は amt を明示乗算 (v5 互換の効き方) — 上記の違いは既知の代用と
