

## 補償品質の定量化と (a,b) の最終結論 (2026-11-04)

### 補償品質の実測 (park_joy フレーム 10↔12)

| 補償 | PSNR(warped, centre) |
|---|---|
| 補償なし | 16.89 dB |
| v5 フロー + 双線形ワープ | 19.93 dB (+3.0) |
| nv_motion フロー (実素材) | 16.74 dB (悪化 — 異常ベクトル -1779px) |

- nv_motion のフローは実素材で壊れる (候補受理が既定設定のまま)。
  合成素材の自己試験は通るが、実素材には本家の settings 値 (image 表) が必要。
- v5 のワープでもブロック平均差の平均 8.62 (ノイズのブロック平均は 0.19) —
  補償残差が支配的。

### (a,b) 補正の最終結論

- v5 warp: PSNR 19.93 / + (a,b) (a=0.883 b=6.56): 20.22 (+0.3 単体)
- E9 パイプライン組み込み (gainab4): Y 38.41 (v5 類似度 38.80 より悪い)
- 回帰が (1,0) から遠いのは補償残差が回帰を汚すため。本家は補償残差が小さいので
  (a,b) が正しく働く。**順序として補償の本家忠実化が先**。
- gainab/gainab2/gainab4 のすべての変体で Y静 が悪化 → 単体適用は見送り。

### 残差の最終整理

E9 の残差の原因は FUN_0098c90c の補償 (ワープ行テーブル + 加重ブロック計測 +
(a,b) + 有効率ゲート) に収斂。bit-exact 検証に必要なのは重み表 0x1561d40 の観測のみ
(ホスト提供構造、静的コードに書き手なし — トークン表と同類)。

### 次の一手 (最短)

Resolve + agent-desktop で本家実行中の 0x1561d40 をメモリダンプ →
重み表の形式確定 → nvh c90c mode 1/2 が通る → 計測/回帰/ワープをビット照合 →
v6 時間段 (c90c 補償 + t=1.3·モデル語3 の pyramid) → E9 再評価。

### 結論

E9 の残差は「補償品質」に収斂し、その改善には
1. 本家の settings 値 (image 表 +0x1D390 の受理係数) を使った nv_motion の品質向上、または
2. c90c の完全実装 (ワープ行テーブル + 加重計測 + (a,b) + 有効率ゲート)
のどちらかが必要。両方ともホスト提供構造 (image 表 / 重み表 0x1561d40) の観測が前提。

## E9 再較正スイープ (2026-11-05、統括)

c90c 近似が閉じた後、残っているノブを最良類似度構成で系統的に掃いた
(`tools/cal_sweep.py`、29 ラン + σ6 検証 8 ラン。評価 JSON は `eval_v6temporal/cal_*.json`)。
共通条件: spatial プロファイル + v6 空間 v6set0 + cn 0.3、σ3/σ6 60 フレーム、interior。

### 結果 (interior PSNR dB、太字 = 全体最良)

| 構成 | park_joy Y/RGB | sintel Y/RGB | old_town_cross Y/RGB |
|---|---|---|---|
| 旧ベスト (pyr1.5/nl0.8/thr4) | 39.75/37.16 | 44.41/42.16 | 37.55/33.95 |
| **全体妥協 (pyr1.2/nl0.8/thr1.5)** | **40.07**/37.46 | **44.69**/**42.51** | **38.02**/**34.31** |
| 素材別最良 (σ3) | pyr1.0: **40.18**/**37.58** | thr2+Cr0.2: 44.70/**42.54** | pyr1.2/nl0.55: 39.66/**36.50** |
| 本家 | 40.30/37.09 | 45.48/43.34 | 37.41/33.59 |

- 全体妥協 (threshold 1.5 + pyramid_scale 1.2、nl/cn は 0.8/0.3 のまま) は
  **3 素材 × Y/RGB のすべてで旧ベストを上回る**。sintel の Cr は −2.29 → −1.43。
- σ6 検証 (本家 36.50/40.43/36.37): 全体妥協は park_joy −0.05 (36.00)、
  sintel +0.33 (39.96)、otc +0.1 程度 (pyr1.2/nl0.7 で 36.91)。σ3 の大幅改善は σ6 でもほぼ保持。
- σ3 だけの最適化は σ6 に転送しない: park_joy pyr1.0 は σ3 +0.43 だが σ6 −0.35、
  otc nl0.55 は σ3 +2.1 だが σ6 −0.09。**既定値の採用は σ3/σ6 の両方で見ること**。

### 各ノブの性質 (観測)

- **threshold は pyramid 類似度では無操作** (pyr が独自のしきい値を持つため。thr2/thr6 の出力が
  ベースと同一)。sintel (sim3c) では thr 4 → 1.5 で Y +0.28/RGB +0.35 (σ3)、+0.33/+0.40 (σ6)。
- **pyramid_scale**: 1.5 (test_v02 の区間 B 較正値) は E9 では過大。park_joy は 1.6 → 1.0 で単調改善、
  otc は 1.2 が最適 (σ3)。σ6 では 1.5 が最適 → 1.2 が両σの妥協点。
- **sintel 色差は過平滑** (`diag_removed`、sim3c): Cr の β 0.890 (ノイズ除去率) に対し
  画像成分の除去 0.67 RMS (本家は β 0.875 で 0.50)。cn を上げると悪化 (0.4 → Cr 50.42、
  0.6 → 48.29)、Cr だけ 0.2 に下げると +0.35。Cb は 0.3 が最適 (0.2 で −0.63)。
 Cr 0.2 の上書きは thr2 と組ませて RGB +0.03 のみ — 採用は見送り (thr1.5 で十分)。
- **sintel Y のギャップは σ ではない**: β 0.724 (当方) vs 0.721 (本家) でノイズ除去率は同じ、
  画像成分の除去が 1.32 vs 1.10 → 補償品質 (既知のボトルネック) の差がそのまま出る。
- **otc の本家参照は入力より劣る** (本家 37.41 < ノイズ入力 38.55、フレームずれなしを確認):
  本家がこの静的素材を過平滑化している。「本家超え」はこの素材では容易で、
  比較の指標としては参考値。
- luma amount (0.6-0.85)・spatial threshold scale (genuine_t 0.9)・nl 0.9 は無効果または悪化。

### 採用

- **E9 プリセット (素材別)**: park_joy/otc = pyramid + pyr1.2 (pj は 1.0 も可、σ6 と格安で取引)、
  sintel = sim3c + threshold 1.5。nl 0.8 / cn 0.3 共通。
- **製品の既定値は変更しない** (threshold 4.0 は test_v02 の実写で較正された値で、
  test_v02 の本家参照は消失済み。E9 は合成ノイズの 3 素材であり、実写での
  threshold 1.5 の安全性は未検証)。E9 プリセットは JSON プリセットとして提供する段階。
