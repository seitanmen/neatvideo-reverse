

## 21. c90c ハーネス: 残る infra (2026-11-04、最終)

### mode 1/2 のクラッシュ原因の特定

1. **rowtab の per-frame ポインタ** (解決): [sp+0xd8] = rowtab+0x40+frame·8 —
   スクラッチ バッファのポインタを格納すれば通る (ただし 9f13bc が成長させるので
   最終的には 9f13bc の割り当てプロトコルの解読が必要)。
2. **重み表 *(0x1561d40)** (未解決): [sp+0xc8] = *(0x1561d40) — __common の大域ポインタで
   **静的コードにストアが存在しない** (トークン表と同じホスト提供構造)。
   9f94ac の重み (行ごとに 16 バイト = 8x int16 とみられる) を構築する必要がある。

### ハーネスの現状

- mode 0 (計測なし): 正常終了 (入口〜記述子〜回帰/ワープの骨格が通る)。
- mode 1/2: rowtab ポインタ修正済み、残りは重み表の構築。
- 9f94ac の重みの形式: x2 = 表の基底、行ごとに +16 バイト、mla.4s で int32 に加重累積。

### 次セッションの最短経路

1. 重み表の内容を本家の実行から観測 (Resolve + agent-desktop でメモリダンプ)、または
   FUN_009f94ac の呼び出し元を遡って重み表の初期化関数を特定。
2. 重み表が埋まれば mode 1/2 が通る → 計測/回帰/ワープをビット照合 → v6 時間段。
