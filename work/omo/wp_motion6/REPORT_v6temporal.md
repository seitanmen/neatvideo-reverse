## 0. 結論

- **目標は未達**。c90c 近似 (均等重みの 32×32 窓平均 + (a,b) 回帰 + 有効率 30% ゲート + 再現側の (1,0) 近傍ゲート) は素材別ベストを下回る (観測):
  park_joy Y 39.75 → **39.35** (目標 40.0)、sintel RGB 42.16 → **41.03** (目標 43.0)。old_town_cross は全ペアがゲートで不適用となり、出力がベースラインとバイト一致。
- 回帰の (a,b) は、ノイズ入りとクリーン素材で小数第 2 位まで同じ値になる (観測、§5)。全ブロックの median(中心 − 隣) は ≈ 0 (−0.04 前後) で、b = +7 規模の大域的なずれはない (観測)。
  → (推定) (a,b) の大きさは補償に失敗したブロック (遮蔽・速い動き) の偏りで決まっており、ノイズや大域的な明るさの変化によるものではない。
- E9 の clean には全体の明滅はない (sintel の Cr を含む。連続フレームの画素差の中央値 0、観測)。ただし sintel はフレーム 49/50 にシーンカットがあり、clamp された (a,b) はすべてカットをまたぐペア (§5)。
  指示 §7 の「sintel の Cr の明滅は sim3c と組み合わせると改善」は、データでは裏付けられない。
- (推定) 本家で害にならないのは、重み表 0x1561d40 を使う加重計測が合わないブロックを抑えているか、本家の補償残差が小さいため。均等重みでは近似にならない (gainab 系の結論を、32×32 窓平均と本家どおりの回帰式で再確認した形)。
  **素材別ベスト構成 (park_joy・old_town_cross = pyramid、sintel = sim3c) は変わらない。**

## 1. 実装 (variant `c90c`)

変更前の控えは `backup/e9_nvm.py.before_c90c` (= HEAD) と、F1/F2 修正前の `backup/e9_nvm.py.before_c90c_r2`。
差分は追加だけ (既存の行で置き換えたのは `--variant` の choices と run.json の辞書の 2 行)。run.json には `spatial_variant` と `env` (NV_NATIVE・NV6_*) も記録するようにした。`worker_init` は全変体で `backend._work` を包むが、出力フレーム番号を `_STATE["idx"]` に書くだけ (ログ用)。

1. **フロー**: `nv.estimate_flow_v5(nb[0], Y, bs, search)` を元の面で計算して `flows` に入れ、同じ dict を基底の時間段に渡す (基底の段は `flows` にあれば再計算しない。補正後の面でフローを推定し直す箇所はない。検証者がコードで確認)。
2. **ワープ**: v5 の `dense_flow` + `warp_plane` (色差は格子とベクトルを 1/2)。
3. **計測**: レコード = フローのブロック格子 (Y 16px、色差 8px)。窓 = レコード − g/2 から 2g×2g (Y は 32×32 を (x−8, y−8) から、色差は 16×16 を (x−4, y−4) から。色差の格子は再現側の設計)。窓平均は積分画像 (double)。
   - **参照 x = 中心フレーム、測定 y = ワープ済みの隣** の同じ位置 (変位ゼロ)。指示 §6 と NOTES §12 (002b6a7 版) に従った。§1 の文字どおりの読み (ワープ前の隣を rint(v) だけずらした窓) は `NV6_C90C_MEAS=shift` として park_joy だけで試した (§4)。
   - 無効 (0xff800001 相当) = 窓、または rint(v) だけずらした窓が面からはみ出すブロック。
   - 2048 除外は `NV6_C90C_EXCL_SCALE` (既定 0 = 無効)。内部尺度が不明のため、一度も有効にしていない。
4. **回帰** (NOTES §12・§13、本家の逆アセンブル 0x98d188〜0x98d2b4 で検証者が確認):
   - 累積は double で Σx・Σy・Σxy・Σyy・n。
   - 有効率 = float32(n)/float32(total)·100 (total は無効ブロックを含む)。≤ 30% なら (1, 0, 0, 0) を返す。分母 0 のときも同じ。
   - a_f = float32((nΣxy − ΣyΣx)/(nΣyy − Σy²))、b = float32((Σx − a_f·Σy)/n)。**b は clamp 前の a_f から計算**し、そのあと a を [0.66f, 1.5]、b を [−64, 64] にそれぞれ別に clamp する (F1/F2 の修正後。修正前は clamp 済みの a で b を計算し、有効率を double で計算していた)。
   - [2] = mean|y − x|、[3] = mean|b + a·y − x|。
5. **適用**: 隣の面を a·p + b に置き換えて基底の段へ渡す (warp(a·p + b) = a·warp(p) + b。最大差 3.1e-5 を確認)。
   - **再現側の発見的ゲート (本家にはない)**: |a−1| < 0.05 かつ |b| < 2 なら適用しない (`NV6_C90C_GATE`、既定 1)。
   - 補正で隣のノイズ分散が a² 倍になる分は、残留ノイズの係数 (NEIGHBOUR_VAR) に入れていない。
6. **基底の類似度**: `NV6_C90C_BASE` = builtin (P の similarity = pyramid) か sim3c。素材別ベストと同じ基底にしたので、差は c90c の効果だけ。
7. **ログ** (`NV6_C90C_LOG`): (フレーム, オフセット, チャンネル) ごとに a・b・有効率・n・[2]・[3]・適用の有無を jsonl に書く。集計は `eval_v6temporal/c90c_stats.py`。
8. **合成画像での自己確認** (観測):
   - 隣 = 0.9·中心 + 5 (Y)・1.1·中心 − 3 (Cb)・恒等 (Cr) に対し、a = 1.11111 / 0.90909・b = −5.5555 / 2.7273。Cr は (1, 0) で不適用。補正後の誤差は 1.5e-5。整数変位を付けても同じ値。
   - clamp の確認: a 0.5 の Cb では a 0.66f・b 35.0。a 2 の Cr では a 1.5・b −20。

## 6. 制限

- **重み表の近似**: 本家の重み表 0x1561d40 (ホスト提供、静的コードに書き手なし) を均等重みで置き換えたのが最大の近似。本結果が示すのは「均等重みの近似は E9 で役に立たない」ことだけで、本家の c90c の効果は示していない。
- **計測の尺度**: 本家の計測の内部尺度は不明。2048 除外と b の clamp ±64 の 8 ビット換算は、尺度によって変わる。
  - 平均が ×4 の尺度なら、2048 除外は 8 ビット換算で 512 に当たって実質発火せず、b の clamp は ±16 に当たる。
  - ×16 の尺度なら、2048 除外は 128 に当たり、多くのブロックが除外される。
  - 本近似は、b の clamp を 8 ビット値で ±64 に置いた (推定)。
- **再現側の設計**: ワープ行テーブル (9fa6b0/9fa83c) とモード 0/1/2 の区別は実装していない。v5 の双線形ワープと、チャンネルごとの独立な回帰で置き換えた。色差の格子は再現側の設計。
- **発見的ゲート**: |a−1| < 0.05 かつ |b| < 2 のゲートは本家にない。
- **参照・測定の割り当て**: 指示の §6 / NOTES §12 に従った (§1 の文字どおりの読みは shift として park_joy だけで試し、差は 0.03 dB)。
- **本家の出力**: 改変した RS バイナリ上の、GPU を使える設定での出力 (CPU との差は PSNR で 0.005 dB 以下、`docs/GPU_STATUS.md` §3)。
- **範囲**: 60 フレーム・σ3 のプログレッシブ 3 素材だけ。σ6・インターレースは実施していない。sintel のベースラインは再実行していない。
