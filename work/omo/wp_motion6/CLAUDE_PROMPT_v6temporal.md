## タスク: c90c 補償の近似実装 + v6 時間段

FUN_0098c90c の解読済みアルゴリズムを Python で実装し、E9 で評価する。
重み表 (0x1561d40) はホスト提供構造で観測待ちのため、**近似**で置き換える:

### 1. 計測の近似 (FUN_009f94ac の代替)

本家の計測 = 32×32 窓の加重平均 (重み = ノイズ分散マップ、ホスト提供)。
近似: **均等重みのブロック平均** (sliding_window_view で 32×32 の mean)。
- 参照位置: ブロック位置 + ベクトル (v5 フロー)
- 測定位置: ブロック位置 (中心フレーム)
- 無効マーカー: 位置が範囲外なら 0xff800001 を書く

### 2. 回帰 (解読済み、そのまま実装)

```
有効ブロック (測定 != 0xff800001) について:
  n, Σx (参照平均), Σy (測定平均), Σxy, Σyy を double で累積
  有効率 = n / total × 100 → 出力[0x10]
  有効率 > 30% かつ (n·Σyy − Σy²) != 0:
    a = (n·Σxy − Σy·Σx) / (n·Σyy − Σy²)  → float32 に丸めて clamp(a, 0.66, 1.5)
    b = (Σx − a·Σy) / n                   → clamp(b, −64, 64)
    出力[2] = Σ|測定−参照|/n, [3] = Σ|(b+a·測定)−参照|/n
  それ以外: 出力 = {1.0, 0.0, 0, 0}
```

### 3. 適用

補償済みネイバー = warped_neighbor × a + b (チャンネルごと、フレームごと)。
(a,b) が (1,0) に近い (|a−1| < 0.05 かつ |b| < 2) 場合は適用しない
(静止領域での悪化を防ぐ — 本家も有効率ゲートで似たことをしている)。

### 4. 評価

`work/omo/wp_motion6/tools/e9_nvm.py` を使って E9 の 3 素材 × 60 フレームを処理し、
`work/omo/wp_e9/tools/e9_eval.py` で評価。

**目標**: park_joy Y 39.75 → 40.0+ (本家 40.30)、sintel RGB 42.16 → 43.0+ (本家 43.34)。

### 5. 実装場所

- `work/omo/wp_motion6/tools/e9_nvm.py` に新しい variant を追加
  (既存の variant のパターンに従う: temporal_v5 をラップして補償を追加)。
- 処理コア (`reference/python/nvfilter.py` 等) は**絶対に変更しない**。
- ワーカーは `NV_NATIVE=0` で実行すること (ネイティブコアは C++ 側でフローを計算するため)。

### 6. 注意

- v5 フロー (`nv.estimate_flow_v5`) を使うこと (nv_motion は実素材で壊れる)。
- (a,b) の回帰は `work/omo/wp_motion/src/nv_motion.py` の `gain_offset` 関数を
  参考にできるが、新しい実装では **32×32 窓のブロック平均**を使う
  (gain_offset は 16×16 ブロックの位置でサンプリングするだけで窓平均ではない)。
- ブロック平均のペア: 参照 = 中心フレームのブロック平均、測定 = 補償済みネイバーのブロック平均。
  両方とも同じブロック位置 (ゼロ変位) でサンプリング。
- 有効率が 30% 以下のときは (1,0) にフォールバック (本家どおり)。
- 色差は Y の (a,b) を流用しない (チャンネルごとに独立して回帰)。

### 7. 期待される効果

- 補償残差が小さいフレームペア (静止〜低速動き) では (a,b) ≈ (1,0) → 変化なし。
- グローバル露出差やフリッカーがあるペアでは (a,b) が補正 → 残差が減る。
- sintel の Cr (明滅) は sim3c と組み合わせることで改善が見込める。
