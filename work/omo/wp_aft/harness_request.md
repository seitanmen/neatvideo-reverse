# WP aft: ハーネス サブコマンド要求 (COMMON §4)

作成 2026-10-17 (WP aft 作業者)。統括の審査待ち。承認前は静的解析と自己一致試験まで進めてある
(`verify/verify_self.py` 143 PASS、REPORT.md 参照)。

## 要求 1: `nvh aftshuffle N`

- 目的: AutoFineTune モード 2 のタイル並べ替え `FUN_009d39ec` の移植 `nv_aft.shuffle_order`
  (nvh なしでは本家との照合が一切できない部品) を本家と直接比較する。
- 呼ぶ関数: `FUN_009d39ec(x0 = long* out, x1 = long n)` (0x9d39ec–0x9d3ae0、57 命令)。
  out に 0..n-1 の順列 (int64) を書く。戻り値なし。
- 出力形式: 各行 `i out[i]` (10 進)。
- 入力の制限: 0 ≤ N ≤ 4096 (AFT の実際の使用は 1080p で 1947)。n=0 は即 return (asm 0x9d39f0)。
- 保護判定・トークン表に触れない根拠: 全逆アセンブル `notes/asm/fn_0x9d39ec.s` (抽出範囲
  0x9d39ec–0x9d3ae0)。外部参照は `adrp x10, 0xc95000; ldr q0, [x10, #0x950]` の 1 件のみ
  (=__TEXT の定数 0..3 の SIMD 初期化用。0x1488000/0x1489000/0x1561000 ページへの参照なし)。
  呼び出し (bl) なし。書き込みは呼び出し元バッファのみ。
- 本家が落ちる入力: 範囲内で知らない (n ≤ 3 はスカラー埋め、n ≥ 4 は SIMD、いずれも自分のバッファのみ)。

## 要求 2: `nvh aftpoly npts ncoef x_1..x_npts y_1..y_npts [q...]`

- 目的: AFT の曲線補間 `FUN_009bdf30` が使う多項式当てはめ `FUN_009d3e8c` (A/b 構築) と評価
  `FUN_009d4890` を、AFT と同じ入力 (x = ビン番号 0..8 の double、y = 比率) で単体比較する。
- 呼ぶ関数:
  - `FUN_009d3e8c(x0 = double* xs, x1 = double* ys, w2 = npts, x3 = double* coef_out, w4 = ncoef)`
    (0x9d3e8c–0x9d41b0)。内部で A (ncoef²) と b (ncoef) をスタックに作り、クラメル
    `FUN_009d41b0` で解いて coef_out へ。
  - `FUN_009d4890(d0 = q, x0 = double* coef, w1 = ncoef)` → double (残りの argv を評価点として)。
- 出力形式: `coef i %.17g` の ncoef 行、続いて `eval q %.17g`。
- 入力の制限: 1 ≤ npts ≤ 16、1 ≤ ncoef ≤ 5、ncoef ≤ npts。
- 保護判定に触れないことの根拠 (開示事項あり):
  - `FUN_009d3e8c` 自身 (notes/asm/fn_0x9d3e8c.s): bl は `_bzero`・`_pow`・`FUN_009d41b0`・
    `___stack_chk_fail` のみ。adrp は 0x13b4000 (stack guard) のみ。
  - **開示**: `FUN_009d41b0` (クラメル、notes/asm/fn_0x9d41b0.s) とその下の `FUN_009d4708`
    (行列式) には `0x1488000/0x1489000` ページ (語 0x1488404 等) と `0x1561000` ページ
    (トークン表ポインタ) を読む難読化様の検査がある (fn_0x9d41b0.s 0x9d41e4–0x9d4260 付近、
    fn_0x9d4708.s 0x9d47f8–0x9d4834 付近)。読み方: 呼び出し後の `cmn` 検査は結果レジスタを
    書き換えない (死に命令) で、出力 (coef) には影響しない — notes/AutoFineTune.md §4b。
    また既存の `nvh curve` は EstimateNoiseLevelCurve の無効ビン補間でこの同一呼び出し鎖
    (9d3e8c → 9d41b0 → 9d4890) を通っており、移植とのビット一致 (23 + 494 入力、
    AGENTS.md §6.5) が既に観測済み — ハーネス環境でこの検査が出力に影響しなかったことの
    実測。単体呼び出しの新規リスクは「同じ鎖を異なる引数で呼ぶ」ことのみ。
- 本家が落ちる入力: 知らない。ただし npts < ncoef の引数は AFT では生じない (knot ≥ ncoef) ので
  制限どおり弾く。ncoef ≤ 0 は本家が未初期化行列で 9d41b0 を呼ぶ経路 (notes §4b) なので除外。

## 要求しないもの (参考)

- `FUN_009b4e08` (66% 分位とビン更新)・`FUN_009b5408` (モード 2 後処理)・`FUN_009b6338` (類似度):
  入力が AFT ワーカーの作業構造 (スタック/ヒープの bins) で、単体呼び出しには親のレイアウト再現が
  要る。Common §3「部品の組み合わせで実行させない」の趣旨にも近いので要求しない (未照合のまま)。
- `FUN_009bdf30` (曲線補間+clamp): **0x9be22c–0x9be29c に難読化様の判定がある** (語 image+0x16af38、
  カウンタ 0x1488404、表ポインタ 0x1561000 ページ +0x68a8、バイト +0x1a15 を読み、カウンタへ書く)。
  逆アセンブルの範囲ではこの書き込みは大域のみ (ビンの値には影響しない — 観測: 系列は 0x1488404
  への str で完結)。判定制の関数を単体で呼ぶ提案には当たるので、要求しない。移植は
  「正しい表なら加算 0」の仮定 (INSTRUCTIONS.md) のまま。
