# WP integrate 報告: 本家と一致したノイズ推定を v5 のデノイズに使う

作成 2026-10-17 (wp_integrate 作業者)。対象: `INSTRUCTIONS.md` (2026-10-16 付) の手順 1〜3。
観測と推定を区別する。数値はすべて実測 (出典ログを付記)。

## 1. 結論 (要素ごと)

### 1.1 リバース: プロファイルのどの語がフィルタの σ になるか (手順 1)

**結論: モデル面ブロック (+0x4c + i·0x1f54, i=0..5) の q99 語 (語 5+k, k=段) がフィルタの σ の基準値。
設定ゲインが語に掛かり (FUN_0099f79c → FUN_0099ce38)、輝度曲線 (+0xbf44) は画素単位の係数として掛かる。**

観測 (逆コンパイル `analysis/rtti/kern/fn_*.c` と自前 `notes/decomp/`。本家は実行していない):

1. **プロファイル → インスタンス複写** `FUN_0099fb7c`: memcpy のサイズ・配置が `nv_profile` のレイアウト
   (6 面ブロック +0x4c から 0x1f54 間隔、輝度曲線 +0xbf44、タイルずれ 0xbc44/0xbd10/0xbddc、mcstats 0xbea8) と一致。
2. **設定 → 語のスケール** `FUN_0099f79c` が `FUN_0099ce38` を呼び、複写の各面ブロックの σ 系語
   (語 0..4 平均・5..9 q99・10..14 中央値・55.. 方向・80+16k・480+・505+・905+) に、
   変換面 (i=3..5) はチャンネル別ゲイン g_c·G、RGB 面 (i=0..2) は方向ミックス係数 (DAT_0147df98) を掛ける。
   mcstats にも帯域別ゲイン。
3. **時間側の閾値** `FUN_0099afb4` (wp_temporal の逆アセンブル `notes/dis/fn_99afb4.s` と合致):
   `t = C_k · 1.1 · s_k · 1.2806249(=√1.64) · 0.9 · |σ_k| (+ 最粗段のみ T²)`、`σ_k = 構造体 + 0x14 + 4k`、
   `C = DAT_012445a8 = (1.06, 1, 1, 1)`、重み `w = clamp((2t − R)/t, 0, 1)` (R = 3×3 RMS)。
   **`+0x14 + 4k` はモデル語 5+k (q99) のスロット**。同じ構造体ポインタから `+0x140 + set·0x140 + 段·0x64`
   (方向語、モデル語 80+16k+set·80 と同じ配置) と -1e6 の無効マーカーも読む → 構造体 = 0x1f54 のモデル面ブロック
   (観測: 自分の fn_0x99afb4.c 読み)。
4. **空間側の閾値** `FUN_0098edb0` → `FUN_00990f74` (wp_spatial ノート §2.5 と独立に一致):
   `t = (σ_cfg[k] + 1e-6) · |model[k]| · 1.1`、`model[k] = model + 0x14 + 4k` (= 語 5+k)。同じランプ式。
5. **輝度変調** `FUN_0099e264` → `FUN_009aae90`: インスタンスの 3 つのモデル値 a_j (+0x11548/+0x1349c/+0x153f0、
   0x1f54 間隔 = RGB 面ブロック) を二乗し、色行列 DAT_0147df80[mode] (モード 1 の輝度行 = (0.089, 0.344, 0.013)、
   BT.601 輝度重みの二乗) で混合、輝度ビン表 (+level·0x404、バイト索引 = 曲線 +0xbf44 の実効表現) で画素ごとに
  掛けて σ² を作る。時間・空間の両方がこの σ² ピラミッドを使う (wp_spatial §2.3・wp_temporal §4 と同一の関数)。

**wp_temporal との食い違い (両方を報告、INSTRUCTIONS 手順 1 の要求)**:
wp_temporal は時間側の `param_13 + 0x14 + 4k` を「スタック上の σ/s 配列 (settings+0xd4/+0xe0 の複製)」と読んだ
(本人のノートで「推定」)。私は上記 3. の根拠 (同じポインタの方向語読み・-1e6 ガード・wp_spatial の独立の
`model+0x14+4k` 読み) から**モデル面ブロック**と読む。settings+0xe0 の s_k は別引数 (s_k′) として
`FUN_0099afb4` に渡っており、σ_k とは別物 (wp_temporal の式も両方を掛けている)。どちらが正しいかは
呼び出しサイトの逆アセンブル (引数レジスタ追跡) で決着する (未実施、下記未解読)。

### 1.2 実装 (手順 2)

`src/nvfilter.py` (SHA-256 `366f1f7e…be0bd`)。`build_profile_v5` に 3 引数を追加 (既定で従来動作・不変):

- `curve_src="genuine"`: 曲線を `nv_curve.genuine_noise_curve` (本家とビット一致の移植) の (xs, ys) で置き換える。
  xs = 16..240 が v5 の curve_centers と厳密に一致することを関数内で検証。ENLC は**輝度のみ**を測るため、
  色差は輝度曲線で代用 (従来どおり CHROMA_GAIN を掛ける。`chroma_gain=False` で素通し = 変種 d)。
- `band_src="model"`: 帯域 σ を `nv_profile.build_profile(rgb, 1, area, lzma=False)` の領域モデルの q99 語から。
  面対応 (モード 1: Y, (R−Y)·0.713, (B−Y)·0.565): Y→面 3、Cb→面 5、Cr→面 4。4:2:0 色差 (半解像度の 4 帯域) は
  フル解像度モデルの帯域 1..4 に対応させる。比は `_noise_shape(sig, 領域の total, 0.6)` を通す。
  負値 (-0.5·|前段| = 本家の「小さすぎる段は無効」規約) は帯域ごとに領域 σ へフォールバックし
  `prof["model_fallback"]` に記録。モード処理の**後**に適用 (当初は前に置いて auto の時間差分比に上書きされる
  バグがあった — 修正済み。修正前の区間 A は (b)=baseline と同一の数値になった)。
- `chroma_gain=False`: 色差曲線に CHROMA_GAIN を掛けない。

補助 `src/calibrate_v5.py` (`59897316…c8c2`): 候補 JSON に `popts` キー (プロファイル引数) を追加。
`src/validate_v5.py` (`e5e095ac…54ee3`): `validate_v5.py [baseline|a|b|c|d]` で変種を選択。
`data/candidates.json` (`36499aa9…c4f9c`): 5 候補 (baseline / a / b / c / d)、params はすべて既定値
(threshold 4, luma 0.7, spatial 2.0 — 参照値 47.12/47.22 と同じ設定)。

### 1.3 比較 (手順 3) — 実写では全変種が baseline 以下。既定の変更は不要。

**区間 A/B (test_v02、本家出力との PSNR dB、Y/Ymov/U/V。COMMON §6 の手順。ログ `logs/calib_296.log`・`logs/calib_560.log`)**

| 候補 | A: Y | A: Ymov | A: U | A: V | B: Y | B: Ymov | B: U | B: V |
|---|---|---|---|---|---|---|---|---|
| baseline auto | **47.117** | **46.983** | **50.985** | 51.179 | **47.222** | **47.050** | **50.920** | **51.189** |
| (a) 本家曲線 | 46.984 | 46.829 | 41.346 | 40.984 | 47.199 | 47.025 | 42.005 | 41.480 |
| (b) モデル帯域 | 46.838 | 46.691 | 50.987 | **51.201** | 47.139 | 46.978 | 50.915 | 51.198 |
| (c) 両方 | 46.988 | 46.841 | 41.445 | 41.300 | 47.175 | 47.001 | 41.906 | 41.657 |
| (d) +色差ゲインなし | 46.988 | 46.841 | 48.561 | 49.446 | 47.175 | 47.001 | 48.888 | 49.819 |

- baseline の再測定は参照値 (A 47.12/50.98/51.18、B 47.22/50.92/51.19) と一致 (ハーネスの健全性確認)。
- **(a) の Y は同等** (A −0.13 / B −0.02 dB。COMMON §6 の「0.05 dB 未満は同等」を B は満たす)。
  ENLC の Y σ は v5 空間曲線より高い (区間 A で 4.01 vs 3.21) ため、luma 0.7/spatial 2.0 という
  空間曲線で較正した設定では過剰除去側に寄る。
- **(a) の色差は不可** (U/V −7〜−9.2 dB)。ENLC は輝度ノイズのみを測るため、色差への流用 (輝度曲線×CHROMA_GAIN
  = σ 13.1/17.3、実測の色差ノイズは σ≈2.5) は過大評価。ゲインを外しても (d) −2.3〜−2.7 dB。
  本家の色差 σ は AutoFineTune の表 (+0xbf44) 由来で、ハーネスでは生成できない (COMMON §3 の保護判定のため)。
- **(b) の Y は −0.28/−0.08 dB**。モデルの帯域比 (フレーム 312 の Y: 1, 0.516, 0.279, 0.165) は
  v5 の領域測定 (1, 0.502, 0.282, 0.168) に近く、時間差分比 (auto) が最良。色差は Y/U/V とも baseline と同等
  (測定比が減衰事前分布 (0.6/段) で飽和し、事前分布の形になったため。フレーム 312 の Cb q99 比は
  1.117/0.901/0.736 で事前分布が上を回る)。
- **合成ベンチ (σ15 白色 RGB ノイズ、`logs/validate_v5.log`、修正後コードで再実行)**:
  noisy 24.54 → baseline 38.70 → (a) 39.23 → (b) 38.98 → (c) 39.35 → (d) 39.42。
  白色・全面等σの理想条件では本家曲線は本物の σ を測るため有効 (+0.53)。実写との差は素材の色ノイズ構造と
  較正済み設定の組み合わせによる。

**統括の判断が要る事項**: v5 の既定は維持を推奨 (実写・合成の両面で既定を上回る変種がない)。
ただし ENLC 曲線そのものは本家とビット一致しており (下記)、「輝度曲線だけ本家化 + 色差は従来の空間曲線」
という混合 (本 WP では実装していない) は A の Y で −0.13 dB なので選択肢になり得る (要相談)。

## 5. 要相談

1. **時間側 σ_k の構造体**: wp_temporal の「スタック配列」読みと私の「モデル面ブロック」読みの決着
   (§1.1・§3)。逆アセンブルの引数レジスタ追跡で判定可能。
2. **混合変種** (Y のみ ENLC 曲線 + 色差は従来空間曲線): 今回の結果から A/B で baseline と同等以下になる
   見込みだが、test.mp4 (GOP ノイズむら) では逆転し得る。実装するかは統括の判断。
3. **(b) の減衰事前分布**: `_noise_shape` の 0.6/段キャップが色差のモデル測定値 (比 ≥1) を全て事前分布に
   置き換えている。キャップなしの生比 (v5 の semantics から外れる) を試すか。
4. **(a)/(c) 向け再較正** (§3): 本家曲線の σ が 25% 高いため、luma/spatial を再較正すれば Y は戻り得る。
   較正コスト (座標降下 1 回) と見合いか。
5. 本家出力の設定が不明のまま較正している点は v5 と同一の制約 (AGENTS §6.3)。
