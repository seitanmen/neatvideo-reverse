## Round 2: APPROVE (ブロッカー 0 件。ログは `verify/round2/`)

- **所見 1・2**: 12 ビットの .m4v と容器に入らない組み合わせ 6 件 (prores→.mp4 / .m4v、ffv1→.m4v / .webm、x265→.m4v、x264→.webm) は、0.4〜0.5 秒・rc=1 で止まった。プロファイルを作らず、トレースバックも出ず、ファイルも残らない。正当な組み合わせは成功する。
- **途中での失敗**: CLI の符号器の ffmpeg を SIGKILL して試した (8 ビット mp4・10 ビット mkv・EXR)。いずれも rc=1 でトレースバックはなく、書きかけは消え、子プロセスは残らない。無関係なファイルは残った。
  - [低] パターンに合う既存の番号のフレーム (`cx_123456.exr`) も消える。
- **所見 3 (NaN/±inf)**: 面全体が非有限、散らした 1,232 個 (NaN の payload を含む)、範囲外の文脈フレームだけ、Mix 1 のいずれも、非有限の標本はビット単位で戻り、ほかは有限だった。UI 6/6、OFX の 32 ビット 3 例も同じ。
  - [低・SPEC の範囲外] 有限の巨大値は壊れる。1e9〜1e15 では区画が 0 になり、1e17 以上では出力の約 61% が NaN になる。3e38 と inf の混在では float32 が溢れる。
  - [参考] FFV1 の float (実験的な実装) は、ほぼ全面 NaN のフレームを可逆に符号化できない例がある (ffmpeg 側)。
  - [参考] 面全体の NaN を 0 に置き換えるため、周りがずれる (最大 0.31)。
- **所見 4・5・6・8**: 直った。
  - 4:2:2 の 323×257 → 322×257。4:2:0 は 259×195 → 258×194。
  - msb 形式の深度の不一致は bayer_*16 の 8 件だけ。
  - [低] `vyu444` を 4:2:0 と誤判定する。
- **回帰**:
  - 8 ビットの 3 件 (test.mp4 ×2・test_v02) は、控え = 新 = Round 1 で、mp4 の MD5 と framemd5 が一致した。
  - 抜き取った Mix 1 と通常処理は Round 1 の出力とバイト一致した。尺度の整合は最大 2。
  - selftest は 55/55、UI の試験は 15/15。OFX は Round 1 と同じ値。py_compile は OK。
