# WP aft: AutoFineTune (0x9a775c) の静的移植

前提: `../COMMON.md`、`Agents.md` §6.5 の AutoFineTune の項、`analysis/rtti/astfqg12AutoFineTune_*`、タイル処理 `0x9b56f4`。
**入口と本体内に保護判定がある。本家に AutoFineTune を実行させること、その判定を回避すること、判定を飛ばして部品を組み合わせて実行させることは禁止** (COMMON §3)。
本体内の判定 (32px タイルの行数への加算) は「正しい表なら 0」と仮定して移植し、仮定であると明記する。

## 手順
1. リバース: 本体の流れ (タイル分割・飽和タイルの除外・2 段モデル・類似度 `FUN_009b6338`・ビンへの集計・66% 分位 `FUN_009b4e08`・
   標本不足ビンの扱い・多項式補間と [0.2, 3.0] の制限 `FUN_009bdf30`・プロファイルへの書き込み先) を命令単位で読み、`notes/` にまとめる。
2. 実装: `src/nv_aft.py` に `auto_fine_tune(rgb, profile_bytes) -> profile_bytes` (書き換えるのは本家が書く欄だけ)。既存の移植 (`nv_model`・`nv_band` など) を再利用する。
3. 比較 (できる範囲):
   - 葉の関数 (`FUN_009b6338`・`FUN_009b4e08`・`FUN_009bdf30` など) が判定・トークン表に触れないことを逆アセンブルで確かめたものだけ、
     単体で呼ぶサブコマンドを COMMON §4 の手順で要求する (統括が可否を判断する)。承認前は静的解析と自己一致の試験 (参照版と高速版) まで。
   - AutoFineTune 全体の本家との一致は確かめられない。報告では「未照合」とする。
   - 間接的な比較: 移植の輝度別係数を使った v5 の変種で区間 A/B の PSNR を測る (COMMON §6)。これは整合性の目安で、一致の証拠ではないと書く。
